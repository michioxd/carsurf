CLAUDE · live dashboard sync — the icon follows the toggle

9f6a1088 · 15:02–16:51

The session that changes the product: live enable/disable on the dashboard, no unplug/replug. Three non-obvious facts unearthed:

win · fact 1

The visible grid rebuilds from DBApplicationController, not the icon-state paths. The CRS/SBS icon-state hooks are dormant on this head unit — no active vehicle connections. Mutating the roster is not enough: firing _didAddApplications:/_didRemoveApplications: right after the mutation is what makes the grid re-render in place.

win · fact 2

The reactive-refresh handler must install before the evaluator gate. CarPlayTemplateUIHost owns the visible grid but lacks CRCarPlayAppPolicyEvaluator, so it never registered the handler. Moving CSInstallCarPlayApplicationLibraryRefresh before the gate fixes the one process that can't react.

win · fact 3

Enable reflow is DashBoard's own behavior — it re-queries allInstalledApplications and rebuilds every declaration in a parallel dispatch_apply loop on load. Cosmetic; disable is smooth. High-risk to fight it (never-hook-hot-paths-in-carkitd).

end of session · what actually happened

The session ends on the session limit at 16:51:48, not on a dropped car connection. CarPlay isn't running at the end; the device is in a bad state after a dozen crash/resprings. The immediate saves: deleting the corrupted CarDisplayIconState.plist clears the stuck grid, and 0.1.4-11 removes the _didAddApplications: crash of builds ≤0.1.4-10. Gravel in the maze · never again

Every crash, and the rule it taught

Seven distinct failure classes over five days. Each one became a memory note with a "how to apply".

01 · EXC_GUARD SIGKILL — FPT Play (crash-reporter apps)

App SIGKILLed ~0.7s after launch: EXC_GUARD, violations ["SET_EXCEPTION_BEHAVIOR"], GUARD_TYPE_MACH_PORT, faulting at task_swap_exception_ports. Isolated to the jbctl trustcache add step alone — the entry sets CS_DYLD_PLATFORM (codeSigningFlags 0x32002001) and drops the team ID, making exception-port setup a guarded op under iOS 18's code-signing monitor. Rule: any app with Crashlytics/KSCrash/Sentry-style reporter needs a real signing cert; trustcache kills it on launch. Reinstall doesn't clear it — only a reboot drops the in-kernel entry.

02 · SIGKILL — CODESIGNING "Invalid Page"

Overwriting a code-signed Mach-O in place (cp -a over it, ldid -S in place) binds the old signature to the vnode; every later reader dies with termination.namespace CODESIGNING, indicator "Invalid Page". Byte-identical copies behaved oppositely. Rule: write a temp file, mv over the target — fresh inode. Audit both restore paths (patch script rollback + helperd CSRevertPatch), which still overwrite in place.

03 · SpringBoard abort — manufactured dictionary

The scene-manifest spoof aborted SpringBoard when entitlementValuesForKeys: manufactured a dictionary after the real callee returned some other type (SpringBoard's FBSApplicationInfo gets an LSBundleInfoCachedValues, not an NSDictionary). Rule: never invent a type you don't own — hand the real object back and tag it, and let the tagged accessors answer capability keys.

04 · CarPlay PAC-failure crash loop (Build 5 · 0.1.4-16, 11 crashes)

EXC_BAD_ACCESS (PAC failure) in a block invoked from -[CRSIconLayoutService fetchIconStateForVehicleID:completion:] with CSSystem.dylib on the stack. DashBoard's getIconStateWithCompletion: segfaults reading a CRSIconLayoutState we reconstructed; garbage top-frame address = jumped through a corrupted/failed-PAC pointer = use-after-free-class crash. Reproduced by rapid toggles and by opening the Customize list of a non-connected vehicle. Rule: the empty-state block guard is what started the loop — Build 4 (pass-through, no guard) never crashed. Reconstruct-and-reserve reconstructed states to DashBoard is where it breaks.

05 · Empty Customize — CSFilterIconLayoutState

The old filter rebuilt pages from a derived/filtered list and dropped every icon it couldn't account for — Settings > Customize came back empty and CarPlay crashed. Rule: rebuild by moving one existing icon object between pages and hiddenIcons; carry every other object (system icons included) unchanged. That's the object-preserving sync in Build 6+.

06 · YouTube unrecoverable launch failure

After a day of patch/reconcile cycles YouTube stopped launching entirely: no launchd job, no crash report, every check green (cdhash trusted, SBStarkCapable present, fresh inode). Nothing on-device could undo it — a fresh App Store install fixed it instantly. Rule: helperd backs up only Info.plist + entitlements, never the binary; when a patched app won't launch and all checks pass, stop bisecting and reinstall from the App Store.

07 · DBApplicationController mutation crash

The earliest live-apply path — mutating DBApplicationController's model directly — crashed before the notifier-callback fix. Rule: mutate roster and fire _didAddApplications:/_didRemoveApplications:; the mutation alone is never enough (see 08-14, fact 1).

The exit, one door at a time

The way out

1 · Make build 19 react live again

Restore the visible reaction that Build 5 (0.1.4-16) had: a toggle must move the icon without entering Customize. Decide un-gate the reload (roster rebuild on every toggle — 0.1.4-16 behavior, cost: reflow on each flip) vs. make the service write redraw the grid. Then the 2-min carsurf-logs check on the CarPlay Simulator: does hiddenIcons sync: wrote new state actually fire?

2 · Stop DashBoard from reconciling the hidden write

Our setIconState: write persists, then DashBoard rebuilds the model and puts the icon back — all-visible within ~2 min. Needs a change to the DBApplicationController-side reconcile, not the icon-state write.

3 · Close the vehicle-ID timing gap

gLastVehicleIdentifier is captured only in the CarPlay process (via certificate serial) and is per-process static — CarPlayTemplateUIHost never has it. First fetch can race the connection. Needs a shared/cached vehicle ID.

4 · helperd: back up the executable

Add executable backup to CSBackupDirectory so CSRevertPatch can undo a damaged binary, not just the plists. Real fix, not polish.

5 · Fix the README install glob

The documented install command still resolves to stale 0.2.0-1-93. Pin to the current 0.1.4-19+debug artifact or glob packages/* by newest mtime.

North star, unchanged

Clean exit: runtime admission only — no on-disk app mutation, no trustcache, no per-app dylib. That's the version that survives App Store updates. The on-disk and runtime paths coexist until the runtime path covers every app.
